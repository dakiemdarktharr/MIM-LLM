# Reproducible MIM-LM v0 protocol

This is a **training-ready prototype protocol**, not a validated paper result. The reference vector MIM-LM with the byte tokenizer, width 192 and two recurrent layers has **1,984,320 trainable parameters** (`mimlm model-size --kind mim --width 192 --layers 2 --vocab-size 259`). The same architecture with the tested 512-piece BPE model has **2,081,472** parameters. Every run writes its **actual** count; changing vocabulary, width, layer count or state head changes it.

## Tensor contract and mathematical path

For a batch of \(B\) independent story windows, input IDs have shape \([B,T]\). A shared tokenizer converts each training text to `[BOS, tokens..., EOS]`, and the train target is the one-token shift: `input_ids = ids[:-1]`, `targets = ids[1:]`. Embeddings are \(E_t\in\mathbb{R}^{B\times d}\); the first ST cell returns \(h_t^1,C_t^1,M_t^1\in\mathbb{R}^{B\times d}\). Each later MIM cell stores \(h_t^l,C_t^l,M_t^l,N_t^l,S_t^l\in\mathbb{R}^{B\times d}\). The LM head maps normalized top-layer \(h_t^L\) to \([B,V]\) next-token logits. Across the full sequence the logits are \([B,T,V]\).

```text
IDs [B,T] → embedding [B,T,d] → ST cell (layer 1: h,C,M)
          → MIM-N(Δ lower h, previous N) → D [B,d]
          → MIM-S(D, previous C, previous S) → T [B,d]
          → C = T + i⊙g; update zigzag M; hidden h [B,d]
          → LayerNorm → LM head → logits [B,T,V]
```

At the first token (`BOS`), `has_prev=False` and the difference signal is zero. On later tokens, direct mode computes \(h_t^{l-1}-h_{t-1}^{l-1}\). In a stack above two layers, cascade mode feeds the preceding MIM differential output to the next MIM-N. A new story or independent training window calls the model with `state=None`, resetting all memories. Masked padding positions freeze recurrent states; the Transformer gets both causal and key-padding masks. Padding targets are `-100` and do not enter cross-entropy. The auxiliary state head, when enabled, predicts a label aligned to the **current input token**; its labels are never fed into the backbone at inference.

Training uses AdamW, gradient clipping, explicit seed, fixed input token budget and full-sequence teacher forcing. The loss is next-token cross-entropy plus an optional weighted state-label loss. `StoryDataset` splits long stories into disjoint target windows of at most `context` tokens; state is reset at each window, so backpropagation does **not** span windows. This truncation is a substantive memory limit and must be reported. At generation, recurrent models consume the full prompt and then carry state one sampled token at a time; the Transformer recomputes the prefix under a causal mask and rejects prompts plus output beyond its configured context. Fair tests must choose a context that holds the entire benchmark prompt plus the maximum continuation for **all** models. Full-sequence and stepwise logits agree in eval mode in the test suite.

## Tokenizer and data boundaries

The UTF-8 byte tokenizer is the minimal audit baseline. The preferred pilot uses SentencePiece BPE with byte fallback, special IDs `PAD=0, BOS=1, EOS=2, UNK=3`, fitted on **training stories only**. The trained model is copied into each run directory and its SHA-256 is recorded. The whole corpus and its SHA-256 are recorded too. For the demonstration supervision corpus, labels describe the key holder's role after each consumed UTF-8 byte. SentencePiece piece-end offsets convert those labels to token-aligned training targets. Real state-supervision experiments need independently constructed and audited state labels; the demonstration labels cannot establish general narrative understanding.

The repository supplies an executable cabinet oracle and a synthetic paired benchmark whose overwrite depth varies from 2 to 5. Its one-premise pairs change the electricity time from 8:55 to 9:05 while retaining the transfer chain. At 9:00 the opening action must flip, while ownership remains unchanged. `lock-benchmark` validates the pair structure and writes a content hash; test generation requires the lock file. The same schema can hold a human-authored licensed source pair with `base`/`perturbed` prompts, one declared changed span, required changed predicates, actual and counterfactual obligations, and facts that must remain true. A pilot consisting only of generated cabinet templates is not enough for a benchmark paper.

TinyStories is imported as a bounded, revision-pinned streaming subset. The public dataset card lists CDLA-Sharing-1.0; its stories were generated for small-model LM research and are **not** a human-written test set. The importer uses official train and validation source splits, then disjointly allocates part of official validation to project validation and project test. Exact duplicate text and source IDs across project splits are rejected. Any other corpus must include `source_id`, `split`, `text`, origin, and a checked redistribution license when released. Keep restricted or uncertain-license texts outside the public repository.

## Evaluation and separation of claims

The primary pre-registered target is the proportion of **3–5 sentence continuations** that express every required proposition and do not contradict the prompt or their own history. Two blind readers should label a representative sample independently; their agreement and any adjudication are recorded. `blind-packet` removes system identity, `agreement` reports field agreement and Cohen's kappa, `adjudication-packet` exposes disagreements, and `finalize-adjudication` rejects unresolved fields. `aggregate-labels` rejects missing labels and bootstraps **source-story clusters**, keeping all premise pairs from one source together; a pair-level success score is also reported. No code path manufactures human judgments. Free text may have many valid continuations, so one reference answer is not used as the consistency target.

Secondary measures include proposition coverage, contradiction rate and type, pair success across both conditions, correct counterfactual outcome, retained invariants, concrete-event rate, fluency and held-out perplexity. The first generated continuation is fixed as **raw token IDs** and re-entered before the second continuation; annotators record the resulting state and judge whether the model honors its own new event. A no-op or generic continuation is counted as evasion even if it contains no explicit contradiction. Invalid UTF-8 decoding or replacement characters are flagged. Automatic lexical overlap and held-out perplexity are diagnostics for writing, not substitutes for logical or human judgments.

The exact same corpus, tokenizer model, source split, number of training targets, decoding settings and selection budget must be used across systems. `matrix` first runs MIM against the learned-pair control with widths chosen to minimize the parameter gap. LSTM, Nested LSTM, Delta-RNN, minGRU, GRU, Transformer, N/S/M ablations and token-shift GRU can follow. The minGRU control uses input-only gates, a linear candidate and a tree-based associative scan for full-sequence training; its stepwise recurrence is checked against that scan. **Parameter matching and cost matching are different experiments.** Run a short pilot on the target device for each architecture and then allocate a separately declared GPU-hour/FLOP budget. Report the residual resource gaps; do not claim an exact FLOP match from the `6 × parameters × tokens` proxy stored in manifests.

## Local hardware and decision gates

Observed 2026-11-25: Windows, Python 3.11.9, ~16 GB RAM, **NVIDIA GeForce RTX 5050 Laptop GPU, 8,151 MiB according to `nvidia-smi`**, PyTorch 2.10.0+cu128 with `torch.cuda.is_available() == True`. There is **no RTX 3060 installed**. A 2,081,472-parameter BPE-512 MIM-LM smoke run (339 train targets, width 192, context 128, batch 2) reached about 148 train tokens/s and 65 MB peak *PyTorch allocated* memory. In a later synthetic throughput check at the same architecture and context, batch 2 processed 4,231 train targets at about 327 train tokens/s; batch 8 processed 4,606 at about 1,007 train tokens/s, using about 66 MB versus 105 MB peak PyTorch allocation. The differing update counts and short runs mean this is a configuration hint, **not** a sustained throughput estimate or quality comparison. A separate 85,792-parameter MIM / 87,872-parameter pair-control smoke comparison used the same 1,024 train targets and tokenizer on 10 TinyStories train stories. Its outputs were not meaningful after this amount of training. No long-run GPU-hour estimate or benchmark claim has been established.

The cheapest challenge to the central hypothesis is a paired MIM-versus-learned-pair pilot with the same training data, token budget, decoded samples, and two or three seeds. If the control ties or wins on changed **and** preserved facts, investigate the benchmark and stop expanding the MIM grid. Expand only if a stable consistency gain survives coverage, fluency, natural-story transfer and cost reporting. If both systems fail basic transitions, repair data/labels or training before testing deeper architectural variants. Include a reserve for implementation bugs and article revision; do not tune repeatedly on the locked test set.
